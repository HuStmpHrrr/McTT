The Core Context of a Fast Context

The Core global context a fast context stands for, behind a sealed module: it is the decoding of the fast data (fc_gctx_eq), but no tactic can reduce it into the decoding functions. firstorder reduces through any transparent definition whatever its Opaque status, and through the type of a Qed constant, and took about ten seconds per call on a goal mentioning the decoding, two minutes in the obligations of TypeCheck. The field fc_gctx_eq of the signature is implemented by a proof (FcDecoding.fc_gctx_eq): it is no axiom, and the theorems using it stay closed under the global context.
The module has a file of its own so that no extracted code has it: the extracted functions take the fast data and read no Core context, so extraction needs nothing of this file, and the decoding functions of Extraction.FastGlobal are not extracted either.
