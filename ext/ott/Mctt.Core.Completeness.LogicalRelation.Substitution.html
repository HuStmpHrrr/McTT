Mctt.Core.Completeness.LogicalRelation.Substitution

Building Semantic Substitutions

These lemmas validate no typing rule, since substitution is an operation and has no rules of its own. They are the tools the case files need: every rule with a premise in an extended context (Π, λ, ℕ-elim, …) is proved by instantiating that premise at a substitution built here.
The target context is always an extension, whose context PER is per_env_extend, so each proof has two halves:
  • Tails: the underlying substitution, from one instantiation of the hypothesis, or from two merged along a shared value.
  • Heads: the extension term, whose four values must land in the head PER of the target. That PER is the one A denotes at the substituted environments, while the hypothesis about the term speaks of A[σ] at the outer ones, so the two must be bridged. per_head is impredicative for this reason: bridging is then saturation of the per_univ_elem irrelevance biconditionals by handle_per_univ_elem_irrel.
The type of an extended context is written A and the extension term M, also because S is nat's constructor, so S[ψ]ʷ in a tactic argument would be read as a name and rejected.

It is not an instance of the lemma above, because Γ ⊨ A[σ] ≈ A[σ] : Typeω@i would need a semantic substitution lemma for types, which the development neither has nor needs. The four environments come from the two judgments about σ ,, M: the tails from the substitution judgment, the heads from the term judgment. sb_wk_extend says the two halves recombine into the substitution in the goal (eval_sub_wk_extend packages this).

The Type Judgment of an Instantiation

The counterpart of rel_typ_of_pi for the other shape a type takes in an elimination rule: B[Id ,, N], the codomain of a Π at the applied argument, or the motive of a ℕ-eliminator at the scrutinee. Every such rule needs the same four values and element PER, so they are computed once here.
The value of B[Id ,, N] at ρ is not ⟦B⟧(ρ ↦ ⟦N⟧ρ): the two differ as soon as B builds a closure, which captures the environment it is evaluated in, and B = λ C #1 already separates them. So the four values are reached through two instantiations of the codomain judgment:
  • along σ ,, N[σ] ≈ σ' ,, N[σ'], whose outer values are the goal's outer ones, since B[Id ,, N][σ] = B[σ ,, N[σ]] (exp_sub_extend_sub);
  • along Id ,, N ≈ Id ,, N at the substituted pair of environments, whose outer values are the goal's inner ones.
The two share no value, so a third instance bridges them: the codomain at the pair of arguments crossing from one to the other. Two merges give the chain from which the goal's four values are selected; this is the three-chain shape of rel_sub_under_ctx_extend_sub, for the same reason.
The element PER is the head PER of B at the arguments the type names, ⟦N⟧(⟦σ⟧ρ) and ⟦N⟧(⟦σ'⟧ρ'). A consumer's chains arrive in the head PER of the arguments they were read at, and per_head_of_args moves them. For that it needs the codomain at an arbitrary related pair, which is therefore reported too, as are N's four values and their domain PER, from which every consumer draws its argument pairs.
