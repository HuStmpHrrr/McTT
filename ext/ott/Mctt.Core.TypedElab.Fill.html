The Typed Fill

The elaborator is untyped: it resolves names into the user syntax (UserSyntax), which holds what is written and nothing else. The command judgment fills each written command into core syntax, in one depth-first pass, before it runs, each part read in the context algorithmic typing (alg_type_infer) reads it in. The core keeps every annotation explicit; the fill writes each one the user may omit:
  • Literals: where the natural numbers are bound (Builtin), a numeral (surface_nlit) stands for the chain of the bound type's constructors and the token ℕ (surface_ntok) for its type former. Without a binding a literal has no fill.
  • Eliminators: an eliminator as written carries no group, no uniform parameters and no sort (surface_elim m Bks M). The group and the parameters are read off its scrutinee's inferred type (elim_target): the eliminator is filled when exactly one reading of it fits its blocks. A block's scrutinee type, when omitted, is the member's type at the parameters and the block's binders.
  • Sorts: the tag of a Π, of an eliminator and of a body's definition is the sort its codomain, motive or type infers to.
  • Omitted annotations (surface_hole): an unannotated let binds its definition at the type it infers; conj (m : P) n proves the conjunction whose second part is the type n infers; an eval without a type is at the type its term infers.
  • Accesses: for e.f the elaborator emits the member f of the module expression e stands for, or, when e is no path, the member f of the term e (surface_proj_term). A term M whose type infers to the record type p at the parameters Rs stands, in module position, for the record's module at Rs, then M (record_value_module): 
        (λ (q : Pair ℕ ℕ) → q.fst)   is filled to   (λ (q : Pair ℕ ℕ) → (Pair ℕ ℕ q).fst)
    A member selected from the module of a record value must be accessible (sel_ok): privacy is checked on the command as written, where the selection is from a term, so it is checked here once the record is known.
A written command is filled to the core commands it runs as: one, or, for a module and a record, the opening of its frame, its body's commands as written, which are filled when they run, and the closing of the frame. The fill reads algorithmic inference (⊢a), which gives one type (functional_alg_type_infer), so the fill, and the run, are functional.

A term as written with no subterm and nothing to fill: its core term.
Definition surface_exp_leaf (M : surface_exp) : option exp :=
  match M with
  | surface_typ n => Some (a_typ n)
  | surface_level n => Some (a_level n)
  | surface_llit o => Some (a_llit o)
  | surface_prop => Some a_prop
  | surface_True => Some a_True
  | surface_tt => Some a_tt
  | surface_False => Some a_False
  | surface_var x => Some (a_var x)
  | _ => None
  end.

M, of the normal type W in Γ, is a type former of an inductive type: W is Πs ending in a universe, and M at the variables they bind is, in normal form, a member of a group of inductive types at its parameters. The inductive alias command premises it, and so does the fill of a local inductive alias.
Definition ind_former (Θ : gdeps) (Ξ : gstack) (Γ : ctx) (M : exp) (W : nf) : Prop :=
  let '(Ds, C) := nf_pi_tele W in
  nf_is_universe C /\
  exists p k Rs, nbe Θ Ξ (Ds ++ Γ) (exp_applied_to_vars M (List.length Ds)) (nf_to_exp C) (nf_indty p k Rs).

M, of the normal type W in Γ, is a type former of a record type, given any prefix of its parameters: W is Πs ending in a universe, and M at the variables they bind is, in normal form, the record type at its parameters. As ind_former, for record aliases.
Definition record_former (Θ : gdeps) (Ξ : gstack) (Γ : ctx) (M : exp) (W : nf) : Prop :=
  let '(Ds, C) := nf_pi_tele W in
  nf_is_universe C /\
  exists p Rs, nbe Θ Ξ (Ds ++ Γ) (exp_applied_to_vars M (List.length Ds)) (nf_to_exp C) (nf_record p Rs).

A member y selected from the module of a record value, the record p when it is one (Some p), is accessible, as glob_ok says of any member of a module named by its path. A selection from any other module is checked as written.
  Definition sel_ok (op : option qname) (y : string) : Prop :=
    match op with
    | None => True
    | Some p => glob_ok Θ Ξ (qname_mod p) y
    end.

The kind of a type whose sort is inferred to be W: ak_propositional at Prop, ak_level at LevelSort, ak_relevant otherwise. It is the kind of a binder over the type, of a Π's domain or codomain, of an eliminator's motive and of a definition. At a sort that is none of these the kind is ak_relevant, and the typing rule rejects the term.
  Definition sort_abs_kind (W : nf) : abs_kind :=
    match W with
    | nf_prop => ak_propositional
    | nf_level_sort => ak_level
    | _ => ak_relevant
    end.

The binder k of Γ holds a term only, an assumption or a definition, and so reads as a term in module position.
  Definition term_binder (Γ : ctx) (k : nat) : Prop :=
    match List.nth_error Γ k with
    | Some (ce_ass _ _) | Some (ce_def _ _) => True
    | _ => False
    end.

The Fill of Terms

fill_exp Γ M M': the term M as written, read in Γ, is filled to the core term M'. The contexts are those of algorithmic typing: a binder's type is its filled type; a let binds its filled definition at its filled (or inferred) type; an eliminator's annotations, motives and branches are read in the contexts alg_type_infer_elim reads them in, at its group and its uniform parameters and filled motives; a local body's entries in the context of the expansion of the filled entries before them (body_xp).

A numeral: the chain of the bound type's constructors
  | fill_exp_nlit : forall Γ n p z s,

The token ℕ: the bound type's type former
  | fill_exp_ntok : forall Γ p z s,
      nat_view Θ Ξ B = Some (p, z, s) -> fill_exp Γ surface_ntok (a_ind p 0)
  
A universe at a level
  | fill_exp_univ : forall Γ M M', fill_exp Γ M M' -> fill_exp Γ (surface_univ M) (a_univ M')

An eliminator as written: its scrutinee filled; its group p and uniform parameters Us the one reading of it that fits its blocks, read off the scrutinee's inferred type (elim_target); its blocks at them and at the filled motives; its tag the sort the filled motive of the scrutinee's member m infers to

The Fill of Commands

Each part of a command is filled in the context its run reads it in. A mutual definition's functions are filled in two steps: their heads, their parameters and scrutinees, from which the group is read (mdef_group), then their results and clauses, in the contexts the eliminator its translation files (mdef_defs) reads them in, at the motives of the translation's own blocks (mdef_blocks).
The head of a function of a mutual definition over Γ, f, its parameters and scrutinee filled, as run_cmd_mdef reads them, to h.

The parameters, over Γ, are filled
