# McTT: Building A Correct-By-Construction Proof Checkers For Type Theories

McTT is a verified, runnable typechecker for Martin-Löf type theory. This project provides an executable, to which we can feed
a program in Martin-Löf type theory to check whether this
program has the specified type. McTT is novel in that it is implemented and verified in
Coq. More specifically, we proved that the typechecking algorithm extracted from Coq is
sound and complete: a program passes typechecker if and only if it is a well-typed
program in MLTT. This is the first verified proof assistant (despite being
elementary) and serves as a basis for future extensions. 

## Online Documentation

We have generated a [Coqdoc](https://hustmphrrr.github.io/McTT/dep.html) for browsing our Coq proof.
The [library](https://hustmphrrr.github.io/McTT/lib/index.html) written in McTT
itself (`lib/`) is browsable too: highlighted, with every name linked to its
definition.

## Architecture

McTT has the following architecture:

```
    | source code of McTT
    v
+-------+
| lexer |          OCaml code generated by ocamllex
+-------+
    | stream of tokens
    v
+--------+
| parser |         Coq code generated by Menhir
+--------+
    | concrete syntax tree
    v
+------------+
| elaborator |     Coq code
+------------+
    | abstract syntax tree
    v
+-------------+
| typechecker |    Coq code
| (normalizer |
|   included) |
+-------------+
    | yes or no    Driver in OCaml
    v
```

In this architecture, most code is in Coq, with accompanying theorems to justify the
implementation.

## Development

Use the toplevel `make` to build the whole project:
```
make
```
Makefile will try to find out the number of your CPU cores and parallel as much as
possible.

Once `make` finishes, you can run the binary:
```
dune exec mctt examples/Nary.mctt # or your own example
```
or more directly
```
_build/default/driver/mctt.exe examples/Nary.mctt # or your own example
```

A program can import units from other files, found under `--search-root`
(the current directory by default). The library `lib/Prelude` proves basic
properties of natural numbers, and `lib/NatTheory.mctt` uses it:
```
dune exec mctt -- --search-root lib lib/NatTheory.mctt
```
`--search-root` may be given more than once; a unit is looked up under each
root in turn.

The natural numbers are not built in.  A unit binds an inductive type of
their shape with `builtin natural ≔ X`.  A unit sees the bindings it makes
and those of the units it imports, directly or not, but never those of a
unit importing it; two bindings of different types meet as an error ("the
natural numbers are bound already").  `lib/Prelude/Builtin/Nat.mctt`
declares `Nat` with `zero` and `succ` and binds it, so a program that uses
numerals starts with
```
import Prelude›Builtin›Nat use (Nat; zero; succ)
```
and is run with `--search-root lib` (as an extra root if its own units live
elsewhere).
The bound type may have other constructor names (`| Z | S (n : Num)`);
an eliminator over it names them as declared.  The interpreter prints the
bound type as `ℕ`, and a chain of its constructors as a numeral.

To build Coq proof only, you can go into and only build the `theories` directory:
```
cd theories
make
```

## External Syntax

Our interpreter accepts a `prog`, defined in the following grammar
(written in
[EBNF](https://en.wikipedia.org/wiki/Extended_Backus%E2%80%93Naur_form)).

Several tokens have a Unicode and an ASCII spelling. The two are the same
token, so either may be used anywhere; the interpreter prints the Unicode
one (and `∀` for `forall`):

| Unicode | ASCII    |   | Unicode | ASCII   |
|---------|----------|---|---------|---------|
| `→`     | `->`     |   | `⊤`     | `True`  |
| `⇒`     | `=>`     |   | `⊥`     | `False` |
| `λ`     | `fun`    |   | `⋆`     | `true`  |
| `∀`, `Π`| `forall` |   | `ω`     | `omega` |
| `≔`     | `:=`     |   | `·`     | `*`     |
| `›`     | `::`     |   | `ω^2`   | `omega^2` |

`ℕ` has no ASCII spelling: it is the type bound as the natural numbers, and
`Nat`, `zero` and `succ` are ordinary names.

An identifier is ASCII letters, digits and underscores, and does not start
with a digit: `x`, `x_1`, `Num2`, `_x`.  A bare `_` is reserved.  A word
that is a keyword (`elim`, `let`, `Level`, …) is the keyword, and a longer
word is an identifier: `elim1` and `Level2` are names.  A numeral and a level
literal start with a digit, so `2l` is the level literal and `x2l` a name.
These symbols need no spaces around them: `λ(x:ℕ)→x` is
`fun (x : ℕ) -> x`.

```EBNF
prog = term , ':' , type;

type = term;
     (* function type *)
term = ( '∀' | 'Π' | 'forall' ) , {parameter} , ( '→' | '->' ) , term
     (* function *)
     | ( 'λ' | 'fun' ) , {parameter} , ( '→' | '->' ) , term
     (* application *)
     | {atomic term}
     (* let expression *)
     | 'let' , let definition , {';' , let definition} , 'in' , term , 'end'
     (* successor of a universe level *)
     | 'succl' , atomic term
     (* join of two universe levels *)
     | 'maxl' , atomic term , atomic term
     (* eliminator of the empty type *)
     | 'exfalso' , term , 'return' , motive
     (* eliminator of a group of inductive types: one block per member,
        in member order, the scrutinee's marked 'at' *)
     | 'elim' , term , elim block , {elim block} , 'end';

            (* universe at the level nat, short for Type@{<nat>l} *)
atomic term = 'Type', '@' , nat
            (* the same, written with the level literal *)
            | 'Type', '@' , nat , 'l'
            (* universe at the level denoted by a term *)
            | 'Type' , '@' , '{' , term , '}'
            (* universe at the level ω, above every finite one *)
            | 'Type' , '@' , ( 'ω' | 'omega' )
            (* universe at ω+nat, short for Type@{<nat>L} *)
            | 'Type' , '@' , nat , 'L'
            (* the large universes, at ω²+nat, above every small one;
               ω^2 is not a level and is written only here *)
            | 'Type' , '@' , '{' , ( 'ω^2' | 'omega^2' ) , [ '+' , nat ] , '}'
            (* the type of the levels below ω·(nat+1); 'Level' is 'Level@0' *)
            | 'Level' , [ '@' , nat ]
            (* the same, braced *)
            | 'Level' , '@' , '{' , nat , '}'
            (* a finite universe level literal *)
            | nat , 'l'
            (* the universe level literal ω+nat, the same level as ω + nat *)
            | nat , 'L'
            (* the universe level literals ω, ω+b, ω·a, ω·a+b *)
            | ( 'ω' | 'omega' ) , [ ( '·' | '*' ) , nat ] , [ '+' , nat ]
            (* the type bound as the natural numbers *)
            | 'ℕ'
            (* the unit type and its element *)
            | ( '⊤' | 'True' ) | ( '⋆' | 'true' )
            (* the empty type *)
            | ( '⊥' | 'False' )
            (* the chain of the bound type's constructors: with Nat bound,
               succ (succ (... (succ zero))) *)
            | nat
            (* variable *)
            | id
            (* parenthesized term *)
            | '(' , term , ')';

parameter = '(' , id , ':' , type , ')';

(* each definition sees the earlier ones *)
let definition = id , ':' , type , ( '≔' | ':=' ) , term
               (* local module *)
               | 'module' , id , ( '≔' | ':=' ) , term;

(* the motive of the eliminator, as a binder: the names of the non-uniform
   parameters, then the scrutinee, which alone may carry its type, then the
   motive's type under them *)
motive = id , '.' , type;
elim block = ( 'at' | 'with' ) , {id} , ( id | parameter ) , ( '→' | '->' ) , type , {elim branch};

(* the names of the non-uniform parameters and the constructor's
   arguments, then those of the induction hypotheses *)
elim branch = '|' , id , {id} , [ ',' , id , {id} ] , ( '⇒' | '=>' ) , term;

id = ? sequence of upper- or lower-case ASCII alphabet characters ?;
nat = ? natural number ?;
```

Here, we omit spaces between tokens. A let-bound variable is
definitionally equal to its definition.

### Inductive types

A module declares an inductive type with a command:

```EBNF
(* the parameters left of ':' are uniform, shared by the members of the
   group; the ones a member's type binds before its sort are not *)
inductive = ['private'] , 'inductive' , id , {parameter} , ':' , member type ,
            'where' , {constructor} , { 'with' , id , ':' , member type , 'where' , {constructor} } ,
            'end';
member type = [ ( '∀' | 'Π' | 'forall' ) , {parameter} , ( '→' | '->' ) ] , type;
constructor = '|' , id , {parameter};
(* a group in its own module T: members T.x, T.y, … *)
mutual = ['private'] , 'mutual' , id , {parameter} , 'where' ,
         'inductive' , id , ':' , member type , 'where' , {constructor} ,
         { 'with' , id , ':' , member type , 'where' , {constructor} } , 'end' , 'end';
(* one function per member of a group, in any order *)
mutual def = ['private'] , ['abstract'] , 'mutual' , 'def' , {parameter} ,
             function , { 'with' , function } , 'end';
function = id , parameter , {parameter} , ':' , type , ( '≔' | ':=' ) , {elim branch};
```

Where a parameter stands decides what it is: written left of `:` it is
**uniform**, the same throughout the type; bound right of `:`, by the type
in front of its sort, it is **non-uniform** and may change from a value to
its recursive arguments.

* **Left of `:`, a uniform parameter.**  It is fixed for the whole type.
  A recursive occurrence passes it back unchanged: `cons (x : A) (xs : List A)`;
  `(xs : List ℕ)` is rejected ("List is not applied to its uniform
  parameters as declared in the argument xs of cons").  The eliminator
  reads it off the scrutinee's type: the motive does not bind it, and
  neither does a branch.  The uniform parameters are the parameters of the
  module `X` the declaration makes.
* **Right of `:`, a non-uniform parameter** (later, with constructor
  results, an index), bound by the type in front of its sort.  A recursive
  occurrence may give it a new value: `step (r : Climb (succ n))`.  The
  motive binds it, then the scrutinee (`at m z -> T`); a branch binds
  the constructor's value of it, then the constructor's arguments, then,
  after an optional comma, one hypothesis per recursive argument, which is
  the motive at that argument's own values (`| step m r, h ⇒ …`, `h` at
  `succ m`).

A recursive argument is the type applied to all its own parameters,
uniform then non-uniform, or a function into it,
`(f : ∀ (n : ℕ) (m : ℕ) → T)`, whose domains do not mention the type; its
hypothesis is then a function too, `h : ∀ (n : ℕ) (m : ℕ) → P (f n m)`, and
the branch receives `λ n m. elim (f n m) …`.  An argument in which the
type does not occur is not recursive; no argument may depend on a
recursive one.  An argument
that is neither as written is read as its normal form, so definitions,
`let`s and transparent members compute first: with
`def Id (X : Type@0) : Type@0 := X end`, `(n : Id N)` is recursive, and
`(f : (fun (X : Type@0) -> ℕ) (N → ℕ))` is the non-recursive `ℕ`.  An
occurrence in the domain of a function (`Neg N` with `Neg X := X → ⊥`,
or `(N → Type@0) → Type@0`) is not strictly positive and is rejected, and
so is one under a head that does not compute: an `abstract` definition, an
axiom or a module parameter.  An occurrence inside a declared type of a
filed group, at its uniform parameters (`(ts : List (Rose A))`), is
nested: the instance becomes a member of the group, a **view**, found from
the arguments and named by the instance; an occurrence in a non-uniform
argument of such a type is rejected.  The type of a non-uniform parameter
must be in the type's sort.

The members of a group, `inductive Tm : Type@0 where … with Sp : Type@0
where … end`, share the uniform parameters and the sort, and each is in
scope in every constructor's arguments.  `mutual T where inductive … end
end` declares the group in its own module `T`.  An eliminator has one block
per member of its group, declared members then views, in that order:

```
elim t at (z : Tm) -> ℕ | var n ⇒ 1 | app f s, hf hs ⇒ succ (add hf hs)
       with (z : Sp) -> ℕ | snil ⇒ 0 | scons t s, ht hs ⇒ add ht hs
end
```

The block marked `at` is the scrutinee's.  The group and its uniform
parameters are read off a block's scrutinee binder type, the first
block's, or else the `at` block's, which must be written when the type has uniform
parameters: `elim l at (z : List A) -> P | …`.  Only that binder may carry
a type.  `mutual def (Δ) f (ys) (z : M) : A := | … with g … end` defines
one function per member, matched to its member by its scrutinee's type,
each the group's eliminator at its member.  The constructor's type is shown with the normal form of
such an argument.  The parameters
of an enclosing module are not written: they are the type's outermost
uniform parameters, as for every member.

The declaration makes `X` a module over its uniform parameters, whose
members are the constructors: `List.cons A x xs` is `(List A).cons x xs`,
and `open List use (nil; cons)` declares them here.  Constructor names need
only be distinct within the type.  As a term, `X`, by its own path, is the
type; a module alias of it (`module L := List`) is a module only: `L.cons`
is `List.cons`, but `L ℕ` is rejected ("L is a module, not a term").  An
inductive alias, `inductive LN := List ℕ` or `inductive L (B : Type@0) :=
List B`, names the type at some of its uniform parameters, under its own
parameters: as a term `LN` is `List ℕ`, and `L ℕ` is too; as a module
`LN.cons` is `(List ℕ).cons`.  It may name an inductive alias in turn, and
may be `private`.  `open … use (X)` declares an inductive alias where `X`
is an inductive type or an inductive alias.  `elim M at … end`
eliminates `M : X …`: the type and its uniform parameters are those of
the scrutinee's binder type.
The module also has the recursor `X.rec`, the eliminator as a function
into a small universe:

```
List.rec : ∀ (A : Type@0) (u : Level) (P : ∀ (l : List A) → Type@{u})
             (bnil : P (List.nil A))
             (bcons : ∀ (x : A) (xs : List A) (r : P xs) → P (List.cons A x xs))
             (l : List A) → P l
```

`examples/Inductives.mctt` has lists, options, trees, dependent pairs, a
type with a non-uniform parameter, Brouwer ordinals `Ord` (with
`lim (f : ∀ (n : ℕ) → Ord)`, also written through a definition `Arr`),
W-types `W A B` (the natural numbers as a W-type, with `elim` and
`W.rec`), and `Grid`, a function shape of two arguments.

## Branches

The Github repo includes the following special branches:

1. `main`: the main branch that is used to generate this homepage and Coqdoc;
2. `ext/*`: branches in this pattern are variations of `main` that implements various extensions. They are often used to implement extensions that require non-trivial workload and are aimed to be merged to `main` eventually;
3. `gh-pages`: the branch to host the homepage.
